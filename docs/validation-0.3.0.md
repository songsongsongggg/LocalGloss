# LocalGloss v0.3.0 稳定版验证

验收日期：2026-10-04（Asia/Shanghai）。测试机器：Apple Silicon、macOS 26.7。维护者授权「测试后无问题发布稳定版」。v0.3.0 与已安装 alpha.5 使用相同运行时代码与固定词库，仅版本、build 13 和发布资料变化。

## 实际 IMK 自动验收

使用 CUA 的原生按键，在两个项目内的独立 AppKit 测试应用中运行已安装的正式 LocalGloss 输入法。测试工具不安装到输入法目录，不进入发行包；只使用固定虚构文字，不读取个人词条文件、真实输入或剪贴板内容。

- `dous` 空格上屏「都是」，`ok` 上屏 `ok`，`jix` 上屏「继续」，`meiy` 上屏「没有」。
- `doushikaifa` 上屏「都是开发」，`woxiangkaifa` 上屏「我想开发」。
- `kafei` + Tab 上屏词典首条释义 `(loanword) coffee`。最初测试期望误写为 `coffee`，核对固定词典后更正期望并重测通过；不记录为产品缺陷。
- `wode` 无译词时，Tab 不消耗拼音；再按空格上屏「我的」。
- 输入框 A 留有 `kaif` 时切到 B，B 输入 `jix` 得到「继续」，未带入 A 的内容。
- 跨两个独立进程切换后，新应用仍正确上屏「继续」，未带入旧会话。
- 标准 NSSecureTextField 聚焦后系统安全输入为 1；预定五个虚构字符仅显示五个掩码。离开密码框后 `dous` 可继续上屏「都是」。未读取密码框正文。
- 关键中文、英文和译词操作重复后结果一致。此为自动按键经过实际 IMK 的测试，不声称是用户物理键盘验收。

## 运行时观察与边界

- 剪贴板变化计数在采样窗口前后均为 94，未读取或替换内容。
- 对 LocalGloss 进程进行 12 次采样、间隔 2 秒：未观察到网络 socket；进程磁盘写入计数始终为 0。
- 本地浏览器测试文件 URL 被浏览器工具安全策略拒绝，未绕过。改为访问项目公开 HTTPS 页面，仅输入虚构测试字母且不提交表单；LocalGloss 和系统拼音均得到原样 `dous`，证明这条浏览器注入路径无法用作 IMK 验收，不列为通过。
- 个别窗口捕获报错后重新读取 AX 状态核对实际结果；不把捕获错误直接算作产品错误或测试通过。
- 采样不能排除短暂连接或缓存写入，不是抓包、完整文件系统追踪或独立安全审计。浏览器、第三方密码框、长期运行、更多应用、物理键盘与其他系统版本仍需继续验收。

## 自动回归与发行检查

沿用 alpha.5 的冻结 181 组样例，不更改样例或基线。正式版本重新运行：371 项 Rust、16 项 Python、Swift 集成、fmt / clippy 和结构性隐私检查通过；181 组候选 174 组首选、181 组前三，4 组同音词顺序下降仍在前三。混输和译词回放在禁止联网及文件写入的核心沙箱中通过。GitHub CI 随发布源码核对。对下载包检查干净源码、版本、签名、文件清单和重新下载 SHA-256。
