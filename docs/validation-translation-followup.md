# v0.3.0 译词与连续输入验收

日期：2026-10-14。状态：用户确认原生 Tab 译词、中英提交、连续输入、焦点切换及浏览器对应译词和词组检查均通过。属于固定样例的用户验收，不是全面兼容性验证。

## 离线回归入口

在已准备 Rust 工具和缓存的开发环境中执行：

```sh
bash scripts/test-translation.sh "$HOME/Library/Input Methods/LocalGloss.app/Contents/Resources"
```

脚本仅读取指定词表和固定样例，在构建目录生成测试产物；不读取个人配置，不切换输入源，不安装应用。`--offline --locked` 禁止 Cargo 下载依赖。执行结果只证明核心行为，不能替代 IMK 上屏验收。

## 真机验收顺序

使用空白本地文稿和物理键盘，选「本地译词」。先确认设置中 Tab 译词已开启；若需要改变设置，由测试者主动保存，测试后恢复原值。

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| T01 | 输入 `kafei`，观察候选，再按一次 Tab | 高亮「咖啡」时提交完整第一释义；默认随包词表为 `(loanword) coffee`。个人主动词条可能改变候选，需单独标记。 |
| T02 | 没有组合时按 Tab | 保持应用原有行为。 |
| T03 | 输入 `wode`；确认高亮「我的」没有译词后按 Tab，再按 Space | Tab 不消耗组合；Space 提交「我的」。若高亮项或释义不同，不判为产品失败。 |
| T04 | 分别输入 `ok`、`dous`，按 Space | `ok`、都是。 |
| T05 | 输入 `doushikaifa`，观察完整组合后按 Space；再用日常速度重试 | 都是开发；没有缺字或残余字母。 |
| T06 | 输入 `kaif` 后切换到另一空白测试输入框，再输入 `jix` 并按 Space | 新会话提交「继续」，不带入旧组合。 |
| T07 | 在浏览器的空白本地测试输入框重复 T01、T05 | 结果与原生文稿一致；不使用搜索、聊天或其他会发送正文的字段。 |

只报告用例编号、应用与系统版本、通过/失败和固定样例结果；不要提供真实正文、个人词条或密码。设置被关闭、工具未触发 IMK、界面工具故障与产品失败分别记录。

## 版本门槛

本轮自动界面入口仍返回 ScreenCaptureKit `-3811`，未继续发送按键。用户先确认「正确输出英文译词」，随后确认「原生和浏览器均通过」。T01、T04、T05、T06 及 T07 对应译词和词组检查按用户报告通过；T02、T03 本轮未单独人工报告，核心自动检查通过。没有复现需要 v0.3.1 修复的产品问题。

只有产品问题在同一应用复现后才进入 v0.3.1 修复。验收收尾后进入 v0.4.0-beta.1 的词条导入/导出开发；发布和本机替换分别验证与确认。
